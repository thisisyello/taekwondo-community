# Taekwondo Community

태권도 커뮤니티 서비스를 위한 React 기반 프론트엔드 프로젝트입니다.
회원가입과 로그인은 Supabase Auth와 PostgreSQL 회원 테이블에 연결되어 있습니다. 게시글 목록/상세·댓글 조회와 게시글/댓글 등록도 DB에 연결되어 있으며, 나머지 게시판 저장 기능은 순차적으로 연결할 계획입니다.

## Tech Stack

- React
- TypeScript
- Vite
- Tailwind CSS
- React Router
- Supabase Auth / PostgreSQL

## Features

- 이메일/비밀번호 회원가입, 이메일 인증, 로그인/로그아웃
- 인증 세션 복원과 토큰 갱신
- 공개 게시판은 인증 확인과 독립적으로 먼저 조회하고, 인증이 필요한 동작만 확인 완료까지 대기
- 인증/내 공감 상태 조회 실패 시 공개 내용 유지와 재시도 제공
- 공용 닉네임과 본인 전용 개인정보 분리 저장
- 게시글 목록 조회
- 로그인 회원의 게시글 DB 등록과 저장 상태/오류 안내
- 작성자 본인의 게시글 수정·삭제, 삭제 확인과 완료 안내
- 로그인 회원의 댓글 DB 등록, 입력 검증과 댓글 수 즉시 갱신
- 다단계 답글 작성, 직접 답한 작성자 표시와 모바일 들여쓰기 제한
- 본인 댓글/답글 수정·삭제와 하위 답글 전체 연쇄 삭제
- 게시판별 게시글 필터링
- 최신순, 오래된순, 댓글 많은순 서버 정렬
- 게시글 최초 5개 조회와 스크롤 시 다음 5개 서버 요청
- 추가 조회 중 중복 요청 방지, 실패 시 기존 목록 유지와 재시도
- 게시글 상세 조회
- 상세 진입당 1회 DB 조회수 증가와 갱신된 값 표시
- 계정당 1회 공감, 취소, 실제 공감 수와 본인의 선택 상태 표시
- 게시글/댓글 조회 로딩, 오류, 재시도와 삭제된 게시글 안내
- 댓글 수 표시
- 제목, 내용, 작성자 기준 검색
- 검색 결과 수와 검색 결과 없음 상태 표시
- 게시글/댓글 작성 폼 유효성 메시지 표시

### List Scroll Behavior

- 게시판 또는 목록 정렬 변경 시 필터 아래의 목록 시작점으로 즉시 이동합니다.
- 검색 제출(같은 검색어 재제출 포함), 검색 대상 또는 검색 정렬 변경 시 검색 결과 안내의 시작점으로 즉시 이동합니다. 검색 입력 폼은 기존 위치에 유지합니다.
- 이동 기준점에는 고정 상단바를 고려한 72px의 상단 여백을 둡니다. 결과가 짧으면 브라우저의 스크롤 가능 범위 안에서 이동합니다.
- 다음 5개 추가 조회, 추가 조회 재시도, 검색어 입력 중에는 프로그램에서 스크롤 위치를 초기화하지 않습니다. 검색 제출 전 대상 변경이나 공백 검색 제출도 이동하지 않습니다.
- 스크롤 이동은 조회 조건 변경/검색 제출 시에만 처리하며, 응답 도착이나 인증 상태 복원 시 반복하지 않습니다. 조건 변경 시 이전 요청을 취소하고 조회 위치, 추가 조회 오류와 마지막 페이지 상태를 초기화합니다.

## Getting Started

Node.js 24 이상을 권장합니다. `.env.local`에 다음 값을 설정합니다.

```env
VITE_SUPABASE_URL=https://your-project.supabase.co
VITE_SUPABASE_PUBLISHABLE_KEY=your-publishable-key
```

`.env.local`은 Git에서 제외됩니다. 관리자용 secret/service_role 키는 프런트엔드에 넣지 않습니다.

### Supabase Setup

1. Supabase SQL Editor에서 `supabase/migrations/202610070001_member_profiles.sql`을 한 번 실행합니다. 새 프로젝트 기준이며 기존 회원은 자동으로 이전하지 않습니다.
2. Authentication 설정에서 이메일/비밀번호 로그인을 활성화하고 이메일 인증을 유지합니다. 최소 비밀번호 길이는 8자로 설정합니다.
3. URL Configuration의 Site URL을 실제 개발 서버 주소로 설정하고, Redirect URLs에 해당 주소의 `/auth/callback`과 `/reset-password`를 등록합니다. 예: `http://localhost:5173/auth/callback`, `http://localhost:5173/reset-password`. 포트나 호스트가 바뀌면 함께 갱신합니다.
4. 일반 사용자에게 인증 메일을 보내려면 Custom SMTP를 설정합니다. 기본 발송은 프로젝트 팀에 등록된 이메일만 지원합니다. [공식 SMTP 안내](https://supabase.com/docs/guides/auth/auth-smtp)

가입 시 DB 트리거가 `profiles`와 `account_details`를 함께 생성합니다. 닉네임은 대소문자와 앞뒤 공백을 무시하고 중복을 금지합니다. 닉네임은 공개 조회 가능하지만 실명, 생년월일, 전화번호는 본인만 조회할 수 있습니다. 역할은 DB에서 기본값 `member`로 부여하며 클라이언트에서 변경할 수 없습니다. 개인정보 입력은 전화번호 본인 인증이나 도장 인증을 의미하지 않습니다.

### Board Database Setup

회원 테이블 생성 후 SQL Editor에서 `supabase/migrations/202610130001_board_posts_comments.sql` 전체를 한 번 실행합니다. 이미 적용한 회원 테이블 SQL은 다시 실행하지 않습니다.

조회수 갱신을 사용하려면 이후 `supabase/migrations/202610140001_post_view_count.sql` 전체를 한 번 실행합니다. 공개 게시글 조회수 증가 함수만 추가하며 기존 데이터를 초기화하지 않습니다.

공감 기능을 사용하려면 `supabase/migrations/202610140002_post_likes.sql` 전체를 한 번 실행합니다. `post_likes`와 조회/저장 함수를 추가합니다. 이 SQL 적용 전에는 공감 정보를 포함하는 게시글 조회가 실패할 수 있습니다.

이후 `supabase/migrations/202611180001_comment_threads.sql` 전체를 한 번 실행합니다. 기존 댓글은 `parent_id = null`인 최상위 댓글로 유지됩니다. 같은 게시글의 기존 댓글에만 답글을 달 수 있고, 저장 후 부모나 소속 게시글을 변경할 수 없습니다. 이 SQL 적용 전에는 `parent_id`를 조회하는 게시글 상세/댓글 기능이 실패합니다. 이미 적용한 이전 SQL은 다시 실행하지 않습니다.

서버 게시판 필터·검색은 `supabase/migrations/202611200001_board_search.sql` 전체를 한 번 실행한 뒤 사용할 수 있습니다. 제목·내용·작성자 닉네임의 대소문자 구분 없는 부분 검색을 지원하며 `%`, `_`, 따옴표는 와일드카드나 SQL이 아닌 문자 그대로 검색합니다. 기존 테이블과 권한은 변경하지 않고 호출자의 RLS를 따르는 조회 함수만 추가합니다. 적용 전에는 전체 목록은 조회되지만 게시판별 필터와 검색은 실패합니다.

이후 `supabase/migrations/202611200002_board_sort.sql` 전체를 한 번 실행하면 댓글 많은순 정렬에 필요한 계산 필드 함수가 추가됩니다. 실제 `posts` 컬럼이나 별도 카운터를 추가하지 않고 답글을 포함한 현재 댓글 수를 조회하며 호출자의 RLS를 따릅니다. 적용 전에는 댓글 많은순 정렬이 실패할 수 있습니다. 기존 SQL은 다시 실행하지 않습니다.

5개 단위 페이지네이션은 기존 테이블/검색 함수의 범위 조회를 사용하므로 추가 SQL 실행은 필요하지 않습니다. 검색 결과 수는 현재까지 불러온 개수가 아닌 전체 일치 개수입니다.

샘플 데이터가 필요하면 `supabase/seeds/board_sample_posts.sql`의 `seed_author_nickname`을 작성자로 사용할 기존 회원의 닉네임으로 바꾼 뒤 SQL Editor에서 전체를 실행합니다. 게시판별 2개씩 총 10개를 추가하며 제목에 `[샘플]`을 표시합니다. 재실행해도 고정 ID가 있는 샘플은 중복 추가하거나 덮어쓰지 않습니다. 기존 글은 변경하지 않으며, 샘플 등록은 마이그레이션과 별개인 선택 작업입니다. 실행하려면 Supabase 프로젝트가 활성 상태여야 합니다.

- `posts`, `comments`는 비로그인도 조회할 수 있고, 로그인 회원은 본인 명의로 작성하고 본인 글만 수정/삭제할 수 있습니다.
- 제목은 200자, 본문은 20,000자, 댓글은 2,000자까지이며 공백만 입력할 수 없습니다.
- ID와 작성/수정 시간은 DB에서 생성합니다. 일반 클라이언트는 작성자, 작성일, 조회수, 댓글의 소속 게시글을 수정할 수 없습니다.
- 게시글 삭제 시 댓글도 삭제합니다. 회원 삭제 시 게시글/댓글은 유지하고 작성자 ID만 비웁니다.
- 댓글 삭제 시 해당 댓글과 그 아래 모든 답글도 삭제합니다. 삭제 대상 댓글의 작성자만 직접 삭제할 수 있지만, 연쇄 삭제되는 하위 답글에는 다른 회원의 답글도 포함됩니다. 형제 댓글이나 다른 게시글의 댓글은 유지합니다.
- 답글은 여러 단계로 연결하며 화면 들여쓰기는 한 단계로 제한합니다. 각 답글에 직접 답한 작성자를 표시하며 댓글 수는 답글까지 포함한 전체 개수입니다.
- 내용이나 게시판 변경 시에만 수정일을 갱신합니다. 조회수 변경과 회원 삭제는 수정일에 영향을 주지 않습니다.
- 화면은 게시글 목록/상세, 댓글과 댓글 수를 DB에서 조회합니다. 조회수와 공감 저장은 전용 DB 함수로 처리합니다. 공감은 게시글/회원 ID 조합을 중복 금지하며 본인의 원하는 상태를 저장하므로 같은 요청을 재시도해도 중복 증가하지 않습니다. 타인의 공감 회원 ID는 공개하지 않고 전체 개수와 본인 상태만 반환합니다. 현재 SQL에는 관리자 계정의 타인 글 수정/삭제 권한이 없습니다.

## Project Structure

- `src/App.tsx`: 전체 상태 관리, 라우팅, 게시글/댓글 이벤트 처리
- `src/lib/supabase.ts`: 로그인 클라이언트와 세션을 기다리지 않는 공개 조회 클라이언트
- `src/hooks/usePostLikes.ts`: 로그인 확인 후 본인 공감 상태 반영, 계정별 응답 구분과 재시도
- `src/hooks/useBoardPosts.ts`: 5개 단위 목록 조회, 다음 페이지 병합, 요청 취소와 재시도
- `src/utils/boardPagination.ts`: 페이지 크기, 마지막 페이지 판별과 중복 게시글 병합
- `src/services/auth.ts`: 인증 요청과 회원 정보 조회
- `src/hooks/useAuth.ts`: 인증 상태 구독과 현재 회원 복원
- `supabase/migrations/`: 회원 테이블, 접근 권한, 가입 트리거 SQL
- `tests/auth.test.mjs`: 입력 검증과 로컬 PostgreSQL 접근 권한 테스트
- `src/pages/auth/`: 로그인과 회원가입 화면
- `src/pages/board/BoardPage.tsx`: 게시글 목록 화면
- `src/pages/board/SearchPage.tsx`: 게시글 검색 화면
- `src/pages/board/PostDetailPage.tsx`: 게시글 상세와 댓글 화면
- `src/pages/board/PostEditorPage.tsx`: 게시글 작성/수정 화면
- `src/pages/dojang/`: 도장 화면
- `src/pages/chat/`: 채팅 화면
- `src/pages/account/`: 내정보 화면
- `src/components/layout/`: 공통 레이아웃, 상단바, 하단바
- `src/components/common/`: 전역 토스트 등 공통 컴포넌트
- `src/components/board/BoardFilter.tsx`: 게시판 필터 버튼
- `src/components/board/PostList.tsx`: 게시글 목록, 정렬, 스크롤 더보기
- `src/components/board/PostItem.tsx`: 게시글 목록 아이템
- `src/components/board/PostForm.tsx`: 게시글 작성/수정 폼
- `src/components/board/CommentForm.tsx`: 댓글 작성 폼
- `src/components/board/CommentList.tsx`: 댓글 목록
- `src/components/board/CommentItem.tsx`: 댓글 아이템과 수정/삭제 메뉴
- `src/data/initialBoardData.ts`: 초기 게시글/댓글 데이터

## Routes

- `/login`: 로그인
- `/signup`: 회원가입과 이메일 인증 안내
- `/auth/callback`: 이메일 인증 복귀
- `/forgot-password`: 비밀번호 재설정 메일 요청
- `/reset-password`: 메일 링크 인증 후 새 비밀번호 설정
- `/`: 게시글 목록
- `/search`: 게시글 검색
- `/posts/new`: 게시글 작성
- `/posts/:postId`: 게시글 상세
- `/posts/:postId/edit`: 게시글 수정

## Current Limitations

- 목록·검색·공개 상세·탐색은 세션 복원을 기다리지 않습니다. 내정보·채팅·글쓰기·수정·인증 콜백 등은 인증 확인 후 진행합니다. 인증 오류는 공개 화면을 가리지 않고 안내와 재확인/로그아웃을 제공합니다. 실제 DB가 중지되었거나 조회에 실패하면 별도의 게시글 조회 오류를 표시합니다.
- 공개 공감 수를 먼저 표시하고 로그인 회원의 선택 상태는 별도로 확인합니다. 확인 중이거나 실패한 경우 공감 버튼은 대기하며, 로그인 복원 때문에 게시글을 다시 조회하거나 조회수를 추가 증가시키지 않습니다.
- 게시글/댓글 등록·수정·삭제는 DB에 연결되어 있으며, 작성자 ID·작성일은 DB에서 설정합니다. 게시글 삭제 시 연결된 댓글과 공감도 함께 삭제됩니다. 댓글 삭제 시 연결된 하위 답글도 함께 삭제되며 별도 복구 기능은 없습니다.
- DB가 비어 있으면 빈 목록을 표시합니다. `initialBoardData.ts`의 샘플 데이터는 자동으로 표시하거나 DB에 저장하지 않습니다.
- 조회수는 상세 조회 성공 후 진입당 1회 증가합니다. 재진입/새로고침은 새 조회로 계산하며 동일 사용자의 반복 조회나 자동화 요청을 서버에서 제한하지 않습니다. 갱신 실패 시 기존 조회수로 게시글을 계속 표시합니다. 비공개 게시판 추가 전 조회수와 공감 함수의 접근 범위도 재검토해야 합니다.
- 비밀번호 재설정은 Supabase 메일 링크로 인증한 뒤 진행하며, 완료 후 현재 브라우저에서 로그아웃합니다. 기본 메일 발송 제한에 걸리면 재설정 메일 요청도 제한됩니다.
- 도장 인증은 아직 연결되지 않았습니다.
- 공감 수는 조회·저장 시 갱신하며 다른 사용자의 변경을 실시간 구독하지는 않습니다.
- 공지와 상단 고정 정책은 아직 확정하지 않았습니다.
- 게시판 필터·검색과 최신순·오래된순·댓글 많은순 정렬은 서버에서 처리합니다. 최신순은 작성일/ID 내림차순, 오래된순은 작성일/ID 오름차순, 댓글 많은순은 댓글 수/작성일/ID 내림차순으로 순서를 고정합니다. 검색 화면은 검색을 제출하기 전 게시글을 미리 조회하지 않습니다. 정렬된 결과의 처음 5개만 요청하고 목록 하단이 보이면 다음 5개를 요청합니다. 조건 변경/재시도 시 첫 페이지부터 조회하며 이전 요청은 취소합니다. 추가 조회 실패 시 같은 위치를 재시도하며 마지막 페이지에서는 요청을 중단합니다.
- 페이지네이션은 offset 방식입니다. 조회 중 다른 사용자가 글을 추가/삭제하거나 댓글 순위가 바뀌면 페이지 경계가 이동할 수 있습니다. 중복 ID는 화면에서 병합하지만 조회 시점 전체를 고정하는 방식은 아니므로 최신 목록은 새로 조회해야 합니다. 각 페이지는 전체 일치 개수를 함께 조회하며, 데이터 규모가 커지면 개수 조회 비용과 커서 방식 전환을 검토해야 합니다.
